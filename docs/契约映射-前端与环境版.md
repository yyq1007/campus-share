## 关键字段差异

### postDetail（9.5）
- 出参：`{ post, isMine, myInteraction:{liked,faved}, commentTotal }`
- `post.likeCount/favCount/commentCount/citedCount` → `post.stats.likeCount` 等（`postFull` 把计数放在 `stats` 下）
- `post.liked/faved` → `myInteraction.liked/faved`（不在 `post` 里）
- `post.createdAt` 存在；`post.publishedAt` 存在
- `authorUid` 不下发 ✓（与前端「不下发 authorUid」约定一致）

### commentList（9.8）
- 出参：`{ list:[{ id, floor, content, createdAt, status, authorUid, replyCount, replies:[{id,floor,replyToFloor,content,createdAt,authorUid}] }], nextCursor, hasMore, total }`
- ⚠️ 环境版 `commentItem` **下发了 `authorUid`**（见下方「待修」）
- 不传 `parentId` → 一级评论 + 每条内嵌最多 3 条二级回复；传 `parentId` → 该评论下的全部回复
- 排序：`floor desc`；`nextCursor` 恒为 `null`，`hasMore` 恒为 `false`（一次性全量）

### commentCreate（9.9）
- 入参：`{ postId, content, parentId?, replyToFloor?, clientReqId }`
- 出参：`{ commentId, floor, status, parentId }`（**没有 `comment` 对象**，前端需自行构造）
- 二级回复：`parentId` 传被回复的一级评论 `_id`；`replyToFloor` 传被回复的楼层号

### meList（9.14）
- `type='posts'` → `{ list:[{ id, title, excerpt, cover, board, status, citedCount, createdAt }] }`；`tab` 仅支持 `'pending'` 与其它（`published/rejected/hidden` 不区分）
- `type='favorites'` → `postBrief[]`（含 `id/shortId/board/title/excerpt/cover/mediaType/likeCount/favCount/commentCount/liked/faved/createdAt/expired/status`）
- `type='messages'` → `{ list:[{ id, type, title, body, count, read, refType, refId, createdAt }], counts:{all,comment,social} }`
- 消息跳转用 `refId`（非 `postId`）

### meOverview（9.13）
- 出参：`{ uid, anonNo, role, status, credit, avatar, nickname, inviteCode, stats:{posts,favs,cited}, unread, canRevoke, config, pendingCount? }`
- `avatar` 为 `{fileId,status}` 对象或 `null`（**不是 URL**）

### meUpdateProfile（9.25）
- 入参：`{ avatarFileId }`；`null`/`''` 恢复默认
- 出参：`{ avatar:{fileId,status} }`
- **不支持改昵称** → S6「编辑昵称」交互需移除或改为只读展示

### reportCreate（9.11）
- 入参：`{ targetType:'post'|'comment'|'user', targetId, reasonCode, reasonText? }`
- `reasonCode` 白名单：`spam/porn/ad/abuse/fake/privacy/other`；`other` 必须带 `reasonText`
- 出参：`{ reportId, reportCount }`

### adminQueue（9.16）
- 入参：`{ tab:'pending'|'report'|'done', cursor?, pageSize? }`
- 出参：`{ list:[{ queueId, targetType, targetId, board, content, media, mediaType, aiLabel, reason, reporterReason, reportCount, source, priority, status, reviewNote, handledBy, handledAt, createdAt }], counts:{pending,report,done}, nextCursor, hasMore }`

### adminReview（9.17）
- 入参：`{ queueId, action:'approve'|'reject'|'hide'|'ignore'|'banUser', reason? }`
- `reject/hide/banUser` **必须带 reason**
- 出参：`{ ok, targetStatus }`
- 举报队列项用 `action:'ignore'` 表示驳回举报（内容保留）

### askQuery（9.12）
- 入参：`{ question, history?, clientReqId }`
- 出参：`{ answer, citations:[{id,title,board,cover,timeText}] }`；无候选时 `{ answer:null, citations:[], guide:true }`

### authLogin（9.2）
- 出参：`{ uid, role, status, needInvite, inviteBound, stats, unread, pendingCount, avatar, inviteCode, canRevoke, config }`
- `needInvite:true` → 跳邀请码页

### authBindInvite（9.3）
- 入参：`{ code }`（6-8 位大写字母数字）
- 出参：`{ uid, inviteCode, stats }`

### postCreate（9.6）
- 入参：`{ board, title?, content, media?:[], fields?, clientReqId, editPostId? }`
- 出参：`{ postId, shortId, status, riskLevel, reason? }`
- 媒体 `fileId` 必须已通过 `mediaCheck`

## 环境版待修点（需改环境函数并部署）

1. **`commentItem` 下发 `authorUid`** —— 违反「接口不下发 authorUid」的匿名化约定（见项目长期约定）。
   环境版用 `authorUid` 是为了前端算 `mine` 标记，应改为下发 `isMine: boolean`。
2. **`postFull` 的计数在 `stats` 下** —— 前端适配即可，无需改后端。
